# 聊天分支树 (Chat Tree Explorer)

把**同一个角色卡**的所有聊天记录合并成一棵可交互的分支树：

- 相同或高度相似的上文只显示一次（共享主干，完全重叠）
- 不同的玩家选择 / 剧情走向分叉成支线
- 每条 AI 消息的所有生成候选（swipes）变成该回合的「变体」，可左右切换
- 每个变体各自的后续剧情继续展开，不会混在一起
- 点击任意节点查看完整消息、出现位置、来源聊天，并可一键打开对应聊天

这是一个纯前端扩展：所有解析都在本地浏览器里完成，聊天内容不会被上传到任何地方，也不会写入磁盘缓存。

---

## 安装

**推荐：在酒馆的扩展面板里直接安装**

在「扩展 → Install extension / 安装扩展」中粘贴：

```
https://github.com/996059396/chat-tree-explorer
```

手机端的其他安装方式（局域网同步、Android USB 拷贝）见 [MOBILE_INSTALL.md](MOBILE_INSTALL.md)。

**手动安装**：把整个 `chat-tree-explorer` 文件夹放到以下任一位置：

- 全局：`data/extensions/third-party/chat-tree-explorer/`
- 当前用户：`data/default-user/extensions/chat-tree-explorer/`

然后重启 TauriTavern（或刷新页面），在「扩展」面板确认 **聊天分支树 (Chat Tree Explorer)** 处于启用状态。

> 本扩展只依赖 SillyTavern 标准前端 API（`SillyTavern.getContext()`、`/api/characters/chats`、`/api/chats/get`），因此在上游 SillyTavern 中也可以使用。

## 打开

- 点击魔棒菜单里的 **聊天分支树** 图标
- 或在聊天输入框执行斜杠命令 `/chattree`

打开后默认显示**当前角色卡**。顶部下拉框可以切换到任意角色卡。

### 树的结构

每一行是一个「回合」：

- **你**：玩家消息。不同聊天里文字相同或高度相似的玩家消息会合并成一个节点；文字不同则成为分支。
- **AI**：角色消息。同一个上文下的所有 AI 生成结果会归入同一个节点，作为**变体**显示。行内的 `‹ 2/3 ›` 可以翻看所有变体。
- 一个 AI 节点的不同变体如果都有后续，会分别展开成支线（变体与后续的对应关系会被记录）。

### 共享主干

所有聊天从同一个开场白开始时，开场白只出现一次，节点右侧显示 `N 聊天`，表示有 N 条聊天经过这里。分支出现的位置会显示 `N 分支`，并用缩进和连接线展开每条支线。

### 变体（swipes）

SillyTavern 的 `swipes` 是 AI 消息的生成历史；本扩展把 `mes`（当前实际内容）和所有 `swipes` 都作为变体保留。因此即使某条消息被手动编辑过（`mes` 不在 `swipes` 里），编辑后的文本仍然会作为独立变体出现，不会被丢掉。

### 连续楼层折叠

长聊天通常会有几十上百个连续的单线楼层。开启「折叠连续楼层」（默认开启）后，连续 6 个以上的单线节点会折叠成一行摘要：

```
[展开 23 层]  AI 你 AI 你 …   开头摘要 … 结尾摘要   23 层 · 4 个变体
```

点击「展开」即可逐层查看。分支点永远不会被折叠。

## 选项

| 选项 | 说明 |
| --- | --- |
| 包含系统消息 | 是否把 `is_system` 消息纳入树。关闭后系统消息前后的内容会直接相连（可能让更多聊天共享主干）。 |
| 合并高相似度消息 | 是否把文字高度相似（但不完全相同）的玩家/系统消息合并为一个节点。关闭后只合并完全相同的文本。 |
| 相似度阈值 | 0.55–1.00。越低越宽松（更多消息合并），越高越严格。默认 0.82。短消息（<12 字符）始终只做精确匹配，避免把「嗯」「好」误合并。 |
| 折叠连续楼层 | 见上。 |
| 只看当前变体的后续 | 默认关闭。开启后，切换 AI 变体时只显示该变体实际产生过的后续分支。如果该变体从未在任何聊天里被选中过（没有已记录后续），会显示全部后续并标注「该变体无后续 · 显示全部」，避免把后面的整段剧情藏掉。 |
| 按聊天着色 | 每个聊天根部一种颜色，分支文件继承同色系的深浅变化。节点右侧的小圆点表示经过该节点的聊天来源。 |
| 分支排序 | 「最近活动」或「最早出现」。 |

左侧聊天列表可以单独勾选/取消某条聊天。取消后立即从树中移除，不需要重新读取文件；重新勾选时会按需读取该文件。

## 数据与隐私

- 通过站内标准接口读取：
  - `POST /api/characters/chats` — 角色卡的聊天文件列表
  - `POST /api/chats/get` — 单个聊天文件的 JSONL 内容（作为 JSON 数组返回）
- 请求头使用 `getContext().getRequestHeaders()`，因此同时兼容 TauriTavern 的本地路由和上游 SillyTavern 的 CSRF 校验。
- 解析结果只保存在当前页面的内存里；关闭面板即释放，不写入 localStorage / IndexedDB。
- 不发起任何外部网络请求，不加载远程脚本，不把聊天内容发送给模型或第三方。
- 渲染使用 `textContent`，不会执行聊天消息里的 HTML/JavaScript。

## 兼容性与已知限制

- 只支持**角色卡**聊天；群聊（group chats）暂未纳入。
- 读取的是**磁盘上的聊天文件**。当前正在聊天但尚未保存到磁盘的最后几条消息可能不在树里；点「刷新」可重新读取。
- 「打开该聊天」调用 `getContext().openCharacterChat()`。不同版本的行为可能略有差异；如果失败会给出提示，不影响浏览。
- 超大角色卡（例如 99 个聊天文件）首次读取需要几秒钟，界面顶部会显示进度。可以取消勾选不需要的聊天来加快速度。
- 聊天文件中的 `swipe_id` 越界、`mes` 与 `swipes` 不一致、`swipe_info` 长度不匹配等情况都已做防御处理。
- 极端情况下（同一上文下有上百个完全不同的 AI 生成结果），变体列表会很长；详情面板内可滚动查看。

## 实现要点

1. **解析**：聊天文件第一行是 header（含 `chat_metadata`），其余每行是一条消息。`mes` 是当前内容，`swipes` 是生成历史，二者可能不一致；两者都会保留。
2. **对齐**：按消息顺序遍历，从根节点开始找当前节点的同角色子节点；先精确匹配，再做 Dice 相似度匹配（字符 n-gram + 词元，带缓存）。低于阈值或过短则新建分支。
3. **AI 归组**：同一上文下的所有 AI 消息属于同一回合，合并为一个节点并收集变体；每个节点记录「哪个变体产生了哪个后续子节点」，从而支持按变体过滤。
4. **血缘**：读取 `chat_metadata.main_chat` 和两种分支文件命名（`<root> - Branch #N`、`Branch #N - <root>`）来确定聊天的根与分支深度，用于着色和侧栏标注。
5. **渲染**：主路径不缩进，只在真正的分叉点缩进；配合连续楼层折叠，即使上千条消息也能快速浏览。

## 排错

- **菜单里没有图标**：确认扩展已启用并刷新页面；也可以在输入框执行 `/chattree`。
- **列表为空**：确认当前角色卡确实有聊天文件；如果刚在别的设备同步过来，点「刷新」。
- **读取失败**：侧栏「选项」里会列出失败的文件与 HTTP 状态；常见原因是文件被其他程序占用或 JSON 格式损坏。
- **打开聊天没反应**：当前版本的 `openCharacterChat` 可能不支持该调用方式；可以直接在聊天历史里手动打开对应文件。
